# 로드맵 — 목표와 방향성

> AI 가 "다음에 무엇을, 왜" 를 판단하는 기준 문서. 방향이 바뀌면 이 문서부터 고친다.

<br>

## 최종 목표

더 좋은 회사의 백엔드 신입 포지션 취업. 이 프로젝트는 그 근거 자료다.<br>
그래서 모든 작업은 **"면접에서 설명 가능한 설계 결정 + 측정된 결과"** 로 끝나야 한다.

<br>

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| Phase 1 | 5개 도메인 + 동시성·페이징·채팅·Saga 측정 + AWS 실배포 | 완료 (2026-05-15) |
| Phase 1.5 | 로컬 실행 복구 — AWS 없이 내 PC 에서 전체 흐름 동작 확인 | 완료 (2026-10-26) |
| **Phase 2** | **AI 를 시스템에 녹이기** — 아래 A, B | **다음 — SPEC-1 부터** |
| Phase 3 | 결제 완성 — 실제 PG (테스트 모드) 연동 + Outbox 로 Saga 빈틈 자동화 | 검토 |
| 마지막 | AWS 재배포 — 면접 직전 시연용 | 대기 |

> 순서 이유: 개발·측정은 전부 로컬에서 한다 (비용 0, 반복 쉬움). AWS 는 시연이 필요할 때만 띄운다.

<br>

## Phase 2 — 왜 하는가

"AI 가 유행이니 챗봇을 넣는다" 가 아니다.<br>
LLM 을 **느리고, 비싸고, 응답이 불안정한 외부 의존성**으로 보고, 결제 PG 처럼 시스템 안에서 문제 없이 동작하게 만드는 백엔드 설계를 보여준다.

### A. 상품 등록 AI 보조 (핵심)

판매자가 제목·설명을 쓰면 카테고리와 가격 범위를 추천한다.

| 문제 | 대응 |
|---|---|
| 응답이 느리다 | 동기 + 타임아웃 + 폴백, 가상 스레드로 대기 중 스레드 점유 완화 ([assist-spec](specs/assist-spec.md) 2-1) |
| 타임아웃 / 장애 | 재시도 + 서킷브레이커 + 폴백 (규칙 기반 카테고리, DB 기반 가격) |
| 응답 형식이 매번 다르다 | JSON 스키마 검증 + 카테고리는 DB 활성 카테고리만 허용 |
| 호출마다 비용 | Redis 사용자별 호출 제한 + 같은 입력 캐싱 |
| 잘 되는지 모른다 | 지연시간, 실패율, 건당 비용, 캐시 적중률, **추천 정확도** 측정 |

역할 분담 원칙: **LLM 은 텍스트에서 정보 추출 (카테고리, 브랜드, 상태), 가격 계산은 시스템 (DB 의 유사 상품)**. LLM 이 가격을 지어내게 하지 않는다.

### B. 작업 AI / 검수 AI 분리 (보조)

같은 모델이 만들고 검수하면 자기 의도대로만 검수한다는 가설.<br>
평소엔 새 맥락의 Claude 검수 에이전트를 쓰고, 작은 실험(버그를 심어 자기 검수 / 새 맥락 / 다른 모델(웹 Gemini) 비교)으로 **측정한 만큼만** 주장한다.<br>
추가 지출은 0원 — 이미 쓰는 구독 안에서만 한다. 운영 규칙은 [ai-workflow.md](ai-workflow.md).

<br>

## Phase 3 — 결제 완성 (검토 단계)

지금 Saga 는 T1 (결제 실패) 만 자동 보상한다 — ADR-5. Mock PG 는 항상 성공하니 나머지 빈틈이 드러나지 않는다.<br>
실제 PG (테스트 모드) 를 붙이면 "결제는 승인됐는데 DB 반영 실패" 가 실제로 생길 수 있고, 이를 Outbox 패턴으로 자동 복구한다.<br>
두 작업은 한 이야기다: **외부 결제를 붙이고 → 생기는 정합성 문제를 → 측정 가능한 방식으로 막는다.** 범위는 ADR-008 에서 정한다.

<br>

## 방향성 원칙

1. **기존 설계 원칙의 확장으로 만든다** — 외부 의존성은 Port/Adapter + Mock + 테스트용 장애 주입 구현 (결제 모듈과 동일 패턴), ADR-1 의존 규칙 준수
2. **AI 가 죽어도 상품 등록은 된다** — AI 는 보조, 핵심 흐름이 아니다
3. **측정 없는 주장 금지** — 수치는 조건과 재현 방법과 함께 기록
4. **새 인프라는 최소로** — 이미 있는 Redis, WebSocket, Actuator 를 우선 사용
5. **A 를 먼저 완성한다** — B 때문에 A 가 늦어지면 B 를 줄인다

<br>

## 하지 않을 것

- 챗봇, 대화형 UI
- LLM 이 최종 가격을 결정하는 구조
- Kafka 등 새 메시지 브로커 도입
- 측정하지 않은 "AI 검수가 더 낫다" 류의 주장
- 실제 비용이 큰 대량 LLM 호출 (부하·장애 테스트는 가짜 LLM 서버로)
